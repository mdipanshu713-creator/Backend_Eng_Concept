In Node.js and Express.js, 200 and 201 are both successful HTTP status codes, but they communicate different outcomes.

## 200 OK vs 201 Created

| Status code   | Meaning                                 | When to use                                   |
| ------------- | --------------------------------------- | --------------------------------------------- |
| `200 OK`      | Request completed successfully          | Fetch user, login, update profile             |
| `201 Created` | A new resource was successfully created | Register user, create product, create project |

## 1. `200 OK` example

Use it when an operation succeeds but doesn't necessarily create a new resource.

```
authRouter.post("/login", async (req, res, next) => {
    try {
        // Validate credentials and generate token

        res.status(200).json({
            message: "Login successful",
        });
    } catch (error) {
        next(error);
    }
});
```

Other examples:

- `GET /users/1` — retrieve user details.
- `PATCH /users/1` — update a user's profile.
- `POST /logout` — complete a logout operation.

## 2. `201 Created` example

Use it when a request successfully creates a new resource.

```
authRouter.post("/register", async (req, res, next) => {
    try {
        // Create a new user in the database

        res.status(201).json({
            message: "User registered successfully",
        });
    } catch (error) {
        next(error);
    }
});
```

Other examples:

- `POST /products` — create a product.
- `POST /projects` — create a project.
- `POST /users` — create a user.

## 3. Quick way to remember

200 = Success

The requested operation succeeded.

201 = Created

A new resource now exists.

## 4. Senior developer interview question

Question: If a user registers successfully, why should we return `201` instead of `200`?

Answer: Because registration creates a new user resource. Returning `201 Created` communicates that creation succeeded and makes the API's behavior more explicit.

One nuance: `201` is appropriate when a resource is created; `200` can also be valid for a successful `POST` operation that doesn't create a resource. For a newly created resource, an API may also include a `Location` header pointing to it.
